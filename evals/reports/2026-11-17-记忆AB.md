# 长对话记忆 A/B 测试（2026-11-17）

## 实验设计

- 同一段 **8 轮**对话，三条臂各跑一遍；每臂独立 `Runtime` + 独立内存 Core（FakeCore）+ **独立会话 ID**
- 模型：真实 DeepSeek（reason=deepseek-flash / fast=deepseek-chat），温度 0
- 记忆事实：`工位在 3 楼东侧，门禁密码 0427`，**明确要求不创建任务**——保证它只能来自记忆，不能靠 `task.search` 查到
- 回忆轮次：第 5 轮（工位/门禁）、第 7 轮（上一轮让完成哪个任务）、第 8 轮（再说一次工位/门禁）

| 臂 | 配置 |
|---|---|
| A 无记忆 | `MEMORY_ENABLED=false` + `CONTEXT_RECENT_TURNS=0` |
| B 固定窗口 3 轮 | `MEMORY_ENABLED=false` + `CONTEXT_RECENT_TURNS=3`（旧行为） |
| C 三级记忆 | `MEMORY_ENABLED=true`，窗口 800 token / 8 轮 + L2 摘要 + L3 事实 |

## 结论

1. **准确率是决定性差异**：没有记忆的两条臂在三个回忆问题上全错（0/3），三级记忆全对（3/3）。
   A/B 的模型甚至明确回答"我没有记忆能力"，而不是编造——说明失败是结构性的，不是模型能力问题。
2. **固定 3 轮窗口等于没有记忆**：第 1 轮的事实到第 5 轮早被挤出，B 与 A 的准确率一样是 0%。
   这说明"只保留最近 N 轮"对长对话不成立，必须有 L2 摘要或 L3 事实兜底。
3. **三级记忆反而更省 token**：C 的输入 token 比 A 少 10.8%、费用少 7.2%。
   原因是回忆轮 C 一步就能答（约 3.7k token），而 A/B 要多搜一次（约 7.2k token），
   但搜也搜不到——多花的那一步是纯浪费。
4. **延迟基本持平**：C 平均单轮 4.85s，A 4.55s，差 0.3s（+6.7%）。
   记忆块本身只有几十 token，代价主要来自多一轮上下文重发，可忽略。

## 局限（如实说）

- **n=1**：只跑了一段对话、每臂一次，token 差异里有一部分来自工具路由的随机选择，不能当统计显著结论；
- **成本**：本次实验总花费约 ¥0.42（三臂各 8 轮）；
- **事实类型单一**：只测了"用户显式告知的私有事实"，没测多轮任务状态回溯；
- 第 7 轮的问题理论上也能通过 `task.search` 碰巧答对（B 就查到了写周报），
  所以"对话历史回忆"这一项的说服力弱于第 5/8 轮的私有事实。
