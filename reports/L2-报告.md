- **ASSUMED: L2 单步模式允许执行 1 个工具**（不是只允许 `meta.finish`）。契约原文是"最多 1 次工具调用 + 1 次措辞"，所以按字面实现"只执行第一个、丢弃其余"；需要确认的破坏性操作在单步模式下**改为问用户**，不越过确认。"不规划"不等于"跳过护栏"。
- **L3 的判定条件 = `ToolError.core_down`**（CoreClient 在传输失败 / 5xx 时打标；工具里未预期的 I/O 异常也打标）。业务错误（404/409/422/幻觉 id）继续喂回模型自纠，不打断整轮 —— 有反向测试 `test_business_error_does_not_abort_the_turn`。
- **429 的处理变更**：从"同策略重试"改成"直接降级"。理由是 provider 已经明确要求别打了，重试只会放大计费；这是 L2 契约"不许用重试代替降级"的直接要求。`test_retry_after_http_date_crashes_current_behavior`（BUG-SP2-26，xfail）未动，仍在。
- **单轮 60s 的落地位置**：放在 `api/chat.py`（整轮入口）。L3 的 watchdog 会在这里补"打印协程栈 + 取消"，所以本层只做"收尾不假成功"，不做栈打印。`turn_timeout_s` 进 config，测试用 0.2s 验证机制。
- **`done.text` / clarify 问题里的协议码过滤是"宁可多抹"**：`redact_protocol_text` 会连裸数字 `501/503` 一起抹。正常业务文案里出现这两个数字的概率极低；如果 L4 需要原样数字，应改从 `errorCode` 字段取，而不是解析文本。
- **L1 的 `_finish_outcome` 里 `_abort` 的 `outcome.aborted` 仍然只记码**（与 L1 一致）；新增的 `degraded/degrade_reason` 在 abort 路径也会带上。
- **prompt 版本**：本层未改 prompt 内容，`system.md` / `system.fast.md` 都是 `version: 4`。L4 报告头必须带 `prompt_version`（本层已把它放进 SSE `done.promptVersion` 与 trace META/SUMMARY 两行，数据源已就绪）。
- **留给 L4 的三条备忘**（按派工口述记录，不改冻结契约）：
  1. `PATCH` 静默忽略 `status` 是 Core 的坑；L4 的 **B7 用例期望 `meta.clarify`**，不是 `task.update` 成功。
  2. `NOT_IMPLEMENTED(501)` 不原样透给用户；L2 已把转译做成 `messages.humanize` + SSE `suggestions`，L4 直接消费 `done.suggestions` / `done.errorCode`。
  3. `prompt_version` 必须进 L4 报告头，否则 v3/v4 数据不可比；本层已把 `promptVersion` 放进 `done` 与 trace。
- **未验证项**：`tests/integration` 37 条仍因沙箱 `tmp_path` ACL `PermissionError` 无法跑完（已试 `--basetemp=.tmp\pytest-int`，仍在 `cleanup_dead_symlinks` 处 WinError 5）。本层改了其中 1 条（F9），需在桌面环境补跑：
