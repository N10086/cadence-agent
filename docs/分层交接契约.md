## 0. 怎么用这份文档

三个角色，职责不重叠：

| 角色 | 职责 | 产物 |
|---|---|---|
| **派工者**（你） | 选层、粘贴提示词、验收层报告、拍板决策 | 一句"开工 Lx" |
| **执行 Agent** | 只做本层、跑本层验收、写层报告 | 代码 + 报告 |
| **验收者**（你或脚本） | 复跑验收命令、核对证据、决定是否进入下一层 | PASS / FAIL |

四条使用规则：

1. **一次只派一层。** 不要把 L0-L5 一次性丢给 Agent——跳层会让它用"看起来能跑"的假实现填坑。
2. **每层必须贴原始输出。** 不接受"已通过""已验证"这类描述，只接受命令原文 + 输出末尾。
3. **验收不过就地回滚，不带着问题进下一层。** 回滚方式见 §7。
4. **每层开始前，Agent 必须先读本层的"前置"和"禁止"。** 这两段比任务清单更重要。

## 1. 全局约定（所有层共享）

> 下面的 G1–G12 要原样出现在每一层的派工提示词里（或明确写"沿用 §1 全局约定"）。

| # | 约定 | 判定方式 |
|---|---|---|
| **G1** | **只做本层**。发现别层的问题，写进报告的"遗留与偏差"，不许顺手改 | 报告的改动文件清单不含别层文件 |
| **G2** | **先读后改**。任何文件在改动前必须先读取；禁止盲写 | — |
| **G3** | **三类东西不可改**：① Core 的 REST 形状（路径/字段/`{code,message,data}`）；② 冻结的验收 spec（`evals/tests/test_sp4_acceptance_spec.py`、`tests/sp3/test_sp3_acceptance_spec.py`）；③ 除本层明确列出的测试外，不许删除或跳过任何测试 | `git diff --stat` 里不出现这些文件 |
| **G4** | **不许为了让测试变绿而放宽断言**。允许的动作只有两种：修实现，或把 `@Disabled`/`xfail` 去掉（本层列明的除外） | 对比测试文件的 diff，断言只许变严 |
| **G5** | **每个改动都要能被一条命令验证**。写不出验证命令的改动，不许做 | 层报告第 2 节 |
| **G6** | **证据格式**：命令原文（可直接复制执行）+ 输出末尾 10 行 + 退出码。禁止截图、禁止转述 | 层报告第 2 节 |
| **G7** | **每层一个 commit + 一个 tag**：`git commit -m "Lx: <一句话>"`，`git tag Lx-done` | `git log --oneline` / `git tag` |
| **G8** | **停机条件**：遇到下列任一情况，**立即停止并提问**，不许自行决定——① 需要改 Core 的 REST 形状；② 需要新增第三方依赖；③ 验收命令跑不起来（环境缺失）；④ 发现两条约定互相矛盾；⑤ 需要改冻结 spec；⑥ 需要花钱（真实 API key） | 提问记录 |
| **G9** | **依赖白名单**：Python 只允许 `fastapi / uvicorn / pydantic / pydantic-settings / httpx / pytest / pytest-asyncio / respx`；本版新增只允许 `pyyaml`。禁止 `typer / jinja2 / sqlalchemy / psycopg / hypothesis` | `pyproject.toml` diff |
| **G10** | **代码规范**：公开函数有类型标注；新增模块顶部一段 docstring 说明"为什么这样设计"；禁止裸 `except:` | 人工抽查 |
| **G11** | **注释写"为什么"，不写"是什么"**。中文 | 人工抽查 |
| **G12** | **拿不准就标 ASSUMED**：按 §8 的默认值实现，并在层报告里写 `ASSUMED: <决策> = <选择>`。禁止静默选择 | 层报告里的 ASSUMED 段 |

## 2. 层级地图与关联

```
L0 地基（修复 + git）
 │  产出：可信的测试基线、version=0 可用、schema 正确、确认令牌有作用域
 ▼
L1 工具契约（function calling 质量）
 │  产出：未知字段拒绝 + 可行动建议、cancel 能力定稿、schema 与 args 同源
 ▼
┌────────────┴────────────┐
▼                         ▼
L2 韧性                     L3 并发与防死锁
│ 熔断 30s、L1/L2/L3 降级   │ 队列/503、信号量、锁超时、watchdog
│ 超时矩阵、degraded 透传    │ load.py 五场景、锁泄漏断言
└────────────┬────────────┘
             ▼
L4 评测（数据集 + 指标 + 报告）
 │  产出：35 条题、runner、14 指标、六表报告、golden 单测
 ▼
L5 前端 + 交付（对话/看板/trace + Dockerfile）
    产出：页面可下单、可看调用链、compose 一键起
```

| 层 | 目标 | 前置（必须已存在） | 交给下游的东西 | 本机可验证？ |
|---|---|---|---|---|
| L0 | 测试基线可信 | 无 | `version=0` 可写、正确 schema、令牌作用域 | ✅ pytest |
| L1 | 工具调用可判对错 | L0 | 统一错误信封、`suggestions`、cancel 语义 | ✅ pytest |
| L2 | 故障降级不崩 | L1（`recoverable`） | `degraded` / `degrade_reason` / `KIND_DEGRADE` | ✅ mock 注入 |
| L3 | 并发不串、不死锁 | L2（超时配置） | 队列指标、锁超时语义、`load.py` | ✅ fake |
| L4 | 有可复现的数字 | L1/L2/L3 | 报告六表、35 条题、指标函数 | ✅ fake |
| L5 | 看得见、装得上 | L2（SSE）、L4（trace） | 页面、Dockerfile、README | ⚠️ Docker 需你本机 |

**关联的三条铁律**：

1. **L0 不完成，L1 的"参数准确率"就是假的**——因为 version 传不进去，模型永远走 clarify。
2. **L1 不完成，L4 的 `arg_acc` 就是假的**——因为未知字段被静默丢弃，"少传一个字段"会被算成成功。
3. **L3 不完成，L4 的 `T_queue` 和并发报告没有数据源**——队列埋点是在 L3 加的。

## 6. 验收脚本约定

每层可以有一个 `scripts/verify/Lx.ps1`，遵循统一语义：

| 退出码 | 含义 | 派工者的动作 |
|---|---|---|
| `0` | 全部 PASS | 看报告 → 放行 |
| `1` | 有 FAIL | 打回本层重做 |
| `2` | 环境缺失（无 Docker / 无 PG / 无 key） | 允许"带条件通过"，但必须在报告标注哪几项未验证 |

输出格式固定：每项一行 `PASS <名称>` / `FAIL <名称> <原因>` / `SKIP <名称> <原因>`。

> 脚本可以后补，但**约定先定**：没有 `PASS/FAIL/SKIP` 三态，就没法区分"真通过"和"没跑"。
