# 03 · 时间路径与风险管理

> 前提：**10 小时/周，共 12 周，单人，单机，零预算**。
> 这份文档的唯一用途是：每个周一打开它，只看当周那一行，做完打勾。

---

## 2. 逐周计划

### W1 · 立项与技术验证（10h）

| 时长 | 任务 |
|---|---|
| 2h | 读完全部 PRD，把"待确认清单"拍板，改掉不适用的部分 |
| 6h | **SP1 Spike**：Java + Spring Boot 起一个 `GET /tasks`，连 Docker 里的 Postgres，写一个测试 |
| 2h | **模型 Spike**：Python 调 GLM-4-Flash，让它输出一个结构化 JSON 的 tool call，看稳定不稳定 |

**产出**：`spike/` 目录（可丢弃）+ M0 结论一句话。
**风险闸门**：如果 Java Spike 超过 8h 还没跑通 → 走 SP1 变体 B（Node/Express）。**不要硬扛。**

---

### W2 · SP1 领域模型与 CRUD（10h）

- 领域建模：Task / Priority / Status / 乐观锁 / 软删除
- Flyway 迁移脚本
- CRUD 五个接口 + 参数校验 + 统一错误响应
- 集成测试（MockMvc）

**产出**：可用的 CRUD API，Postman 集合。

---

### W3 · SP1 领域深度（10h）+ 契约冻结

- RRULE 重复规则展开（`ical4j` 或手写子集：DAILY/WEEKLY/MONTHLY）
- 任务依赖 + 循环检测
- 冲突检测（同一时段重叠）
- `springdoc` 导出 `openapi.yaml`
- 契约测试

**M1 验收**：Swagger 全绿，`openapi.yaml` 提交。

> 这周是"传统项目含金量"的关键。跳过它，整个项目就退化成教程复刻。

---

### W4 · SP2 骨架（10h）+ SP4 数据集 v1

| 并行 | 内容 |
|---|---|
| SP2（7h） | FastAPI 骨架、配置、LLM 客户端、模型路由、工具注册表、单轮 loop |
| SP4（3h） | 评测集格式定义 + 手写 20 条单轮用例 |

**产出**：能跑通"你好 → 查今天的任务"这一条最短路径。

---

### W5 · SP2 闭环（10h）

- 多步循环状态机 + 步数预算
- 会话状态 + 摘要压缩 + **会话级串行化**（`asyncio.Lock`，防并发覆盖，见 D8）
- `guard` 模块：参数校验、id 白名单、危险操作确认
- Trace 落盘

**产出**：S1 剧本（多步意图）可端到端跑通。

---

### W6 · SP2 韧性（10h）

- 失败矩阵全部落地（9 类）
- **熔断器 + 四级降级链**（见 D7）
- 流式输出（SSE）+ **循环与连接解耦**（`stream_id` + `Last-Event-ID` 续传）
- 重试 / 退避 / 429 处理 / 超时
- 集成测试

**M2 验收**：人为制造 5 种故障（含 provider 熔断、SSE 断流），系统都能优雅降级。

---

### W7 · SP3 意图解析（9h）

- 自然语言 → 约束模型（日期解析用规则、意图用快模型）
- 歧义检测规则集
- `meta.clarify` 流程

> 工时说明：SP3 总计 26h，W7-W9 按 9/9/8 分配。SP4 的 Runner 不在这三周里做，集中到 W9 末尾 2h 先跑通首版，W10 再做平台化。

---

### W8 · SP3 重排期求解器（9h）

- 约束建模（硬约束 / 软目标）
- 贪心 + 局部修复算法
- `dry_run` diff 输出
- 纯函数单测（这是最容易写测试的部分，务必写满）

---

### W9 · SP3 分解与主动建议（8h）+ SP4 全量跑分（2h）

- 任务分解（DeepSeek）+ 工时估算 + 草案确认流
- 主动建议引擎（规则触发 + 措辞生成）
- 评测集补齐到 125 条，跑第一版全量

**M3 验收**：三个剧本全部可演示；评测报告 v1 出炉。

---

### W10 · SP4 平台化（10h）

- 指标计算 + 基线对比（裸 prompt vs 加护栏）
- 静态报告页（HTML，够用即可）
- Trace 时间线查看器
- GitHub Actions：PR 触发 smoke（20 条，<3min）

**产出**：一张"加了护栏之后幻觉率从 12% 降到 0%"的对比表——这是简历上最硬的一块。

---

### W11 · SP5 界面与打磨（10h）

- 单页前端：对话区 + 任务板 + diff 确认弹窗 + trace 抽屉
- 用 htmx 或原生 JS，**不要上 React 全家桶**（省 5h）

## 3. 如果延期：砍功能顺序

按这个顺序从后往前砍，**砍到哪一格都还能交付一个完整项目**：

| 优先级 | 功能 | 砍掉后损失 |
|---|---|---|
| 1（先砍） | SP5 前端界面 | 用 curl / Postman 演示，损失观感不损失能力 |
| 2 | 主动建议引擎 | 少一个亮点，主线不受影响 |
| 3 | 任务分解（S2） | 少一个剧本，重排期（S3）仍在 |
| 4 | 重复规则 RRULE | 传统系统降级为普通 CRUD |
| 5 | 任务依赖 | 同上 |
| 6 | 冲突检测 | 同上 |
| **不可砍** | SP1 CRUD / SP2 闭环 / SP4 评测 / S3 重排期 | 砍掉任何一项，项目就不再是"Agent 项目" |

> 判断标准很简单：**能不能用一句话说清"这个 Agent 解决了什么别人解决不了的问题"**。能，就还能投；不能，就继续做。

## 4. 风险登记表

| # | 风险 | 概率 | 影响 | 缓解措施 | 触发信号 |
|---|---|---|---|---|---|
| R1 | Java 学习成本超预期 | 高 | 高 | W1 Spike 做闸门；超 8h 立即切 Node 变体 | W1 周五还没跑通 GET |
| R2 | GLM-4-Flash 工具调用不稳 | 中 | 高 | 双模型路由；关键路径走 DeepSeek；schema 简化 | 单轮工具调用成功率 < 80% |
| R3 | 评测集标注太耗时 | 高 | 中 | 先 20 条跑通格式，之后每周补 10 条，不集中做 | W4 结束不足 20 条 |
| R4 | 重排期算法写不出来 | 中 | 中 | 先做贪心（保证能跑），局部优化作为增强；有 CP-SAT 兜底 | W8 中还没输出任何 diff |
| R5 | 范围蔓延（想加 RAG / 多 Agent） | 高 | 高 | Non-Goals 写死；新想法一律进 `BACKLOG.md`，不在当期做 | 出现"顺便也做一下" |
| R6 | 考试周 / 实习冲突 | 中 | 高 | 12 周计划里 W12 是缓冲；砍功能顺序已备好 | 连续两周未达标 |
| R7 | 免费额度用尽 | 低 | 中 | 评测结果缓存（同输入同输出直接复用）；smoke 集走缓存 | 429 频繁出现 |
| R8 | 做完了但讲不出来 | 中 | 高 | 每个里程碑结束写 200 字"这段我学到了什么"，直接攒成面试稿 | M2 时还说不清架构 |

## 5. 每周节奏（建议）

| 时段 | 做什么 |
|---|---|
| 周一 30min | 读本周计划，拆成 3-5 个可勾选任务，写进 `TODO.md` |
| 周三 10min | 检查进度是否过半，不对就砍范围 |
| 周五 30min | 提交 + 写 200 字周记（**这 200 字就是未来的面试稿**） |
| 周日 | 不写代码，只读自己的代码，找"如果面试官问这里我怎么答" |
