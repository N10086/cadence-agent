## 一句话定义

**Cadence 是一个双层系统：下层是任何公司都有的传统 CRUD 任务后端，上层是一个会澄清、能规划、可评测、敢说"不"的 Agent 协作层。**

它不是一个"用自然语言增删改查"的玩具，而是一次完整回答下面这个问题的工程实践：

> 当一个不可靠的概率模型被接入一个要求确定性的传统业务系统时，需要补上哪些东西，它才敢上线？

这个问题，就是 AI 应用开发岗的日常。

## 命名与术语

| 术语 | 含义 |
|---|---|
| **Cadence** | 项目名，意为"节奏"。指代系统真正要管理的东西：任务的节奏 |
| **Core** | 传统任务后端（Java / Spring Boot），真相来源（source of truth） |
| **Agent** | Python 运行时，负责理解、规划、调用工具、解释结果 |
| **Brain** | Agent 内部的领域智能模块（规划、重排期、主动建议） |
| **Eval** | 评测平台，离线跑分 + 回归 |
| **Trace** | 一次对话中所有 LLM 调用与工具调用的完整记录 |

## 全局技术决策（ADR-lite）

| # | 决策 | 选择 | 理由 | 备选 |
|---|---|---|---|---|
| D1 | 传统后端语言 | **Java 17 + Spring Boot 3** | 国内企业后端主流；"给存量 Java 系统加 Agent"是最有说服力的叙事 | Node/Express、Go/Gin（见 SP1 变体） |
| D2 | Agent 运行时 | **Python 3.11 + FastAPI** | LLM 生态、异步流式、评测工具都在 Python | — |
| D3 | 模型策略 | **GLM-4-Flash 打底 + DeepSeek 兜推理** | 免费额度跑得起评测；难度分层，本身就是成本工程 | 全 DeepSeek（贵 20 倍）、本地 Ollama（工具调用不稳） |
| D4 | 解耦方式 | **只在 Core/Agent 之间划进程边界**，其余用模块边界 | 学生单机跑 4 个服务是自找麻烦；模块边界零运维成本 | 全拆微服务（❌ 明确不做） |
| D5 | 存储 | **PostgreSQL 16（Docker，端口 5433）**，测试走 Testcontainers | `timestamptz` 是"日期解析 100% 正确"的前提；H2 对 timestamptz / 数组 / JSONB 支持不完整，会造成测试与生产行为不一致 | MySQL（TIMESTAMP 时区语义坑）、H2（❌ 已否决） |
| D6 | 评测执行 | **本地 CLI + GitHub Actions 跑 smoke** | 免费、可控、可复现 | LangSmith 等 SaaS（作为可选增强） |
| D7 | 熔断策略 | **只对 LLM 做熔断 + 四级降级**；Core 只做超时快速失败 | 外部依赖会限流；对内部依赖熔断没有收益，只是把超时换成 503 | 全局熔断（❌ 粒度过粗） |
| D8 | 并发控制 | **会话级串行化**（进程内 `asyncio.Lock`），不引 Redis | 并发写同一会话状态会互相覆盖，表现为"AI 忘了刚说的话" | Redis 分布式锁（单机无必要） |
| D9 | 多写失败 | **不回滚，但报告进度**（"已完成 1/2"） | 回滚本身也是写操作，可能再次失败，状态会更乱 | 补偿事务（过重，收益低） |

## 明确不做的事（Non-Goals）

写清楚不做什么，比写做什么更重要。以下内容一律不碰，防止项目失控：

- ❌ 多用户 / 登录 / 权限体系（单用户，`user_id` 硬编码为 1）
- ❌ 移动端 / 小程序
- ❌ RAG 知识库、向量数据库（与主线无关，是另一个项目）
- ❌ 微服务、K8s、服务网格
- ❌ 自研模型微调
- ❌ 实时协作 / WebSocket 多人同步
- ❌ 支付、通知渠道对接（邮件/短信只用 mock）

## 资源约束（写死在方案里的前提）

| 约束 | 值 | 对方案的影响 |
|---|---|---|
| 时间 | 8-12 周 × 10h/周 ≈ 120h | 总计划 114h，只剩 6h 缓冲 → 必须有砍功能预案（见 `03-roadmap.md`） |
| 算力 | 单台 Windows 笔记本，无 GPU | 全 API 调用，不本地推理 |
| 预算 | ≈ 0（GLM-4-Flash 免费额度 + DeepSeek 按需） | 评测集规模受限，必须做缓存与增量跑 |
| 部署 | 本地 Docker Compose | 不做云上部署，demo 视频代替线上地址 |
| 人力 | 1 人 | 所有子项目共享同一套契约，避免联调成本 |
